# Browser regression tests

Run from the repository root with Python 3.12 or newer:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
python -m unittest discover -s tests -v
```

On Linux, if browser system libraries are missing, use
`python -m playwright install --with-deps chromium`.
An existing `chromium` executable is used automatically; set `CHROMIUM_PATH`
to select another executable (including Chrome or Arc's Chromium executable).
Otherwise Playwright uses its downloaded Chromium. The tests start their own
HTTP server on a free port and create an isolated browser context per test;
no running app server, account, network connection, or physical microphone
is needed after installation. Uncaught JavaScript errors fail each test.

## Expanded edge cases

`test_edge_cases.py` adds four groups:

1. Explicit decimal/binary scoring fixtures for short, odd, full and partial
   rows, blanks, partial answers, first/last errors, and one/two errors per row.
   A browser flow also recalls a five-digit sequence with a one-digit final input.
2. Timer/keyboard cleanup after cancellation and navigation, cancelled delayed
   association callbacks, audio source cleanup and restart, double-start races, cancellation during
   asynchronous audio preparation, retry after resume failure, and duplicate
   answer submission.
3. Random-access position/next/mixed questions, mixed association directions,
   multi-number flash, word answers, adaptive and fixed flash timing, metronome
   acceleration and its minimum tempo. Flash timers use the controlled browser
   clock so short displays cannot be missed by test-process timing.
4. Denied localStorage reads, quota errors, malformed JSON, wrong-shaped JSON,
   denied/asynchronously failing IndexedDB opens, throwing transactions, and
   transaction aborts. Faults are injected only in isolated browser contexts.
   Valid statistics are preserved while invalid entries are discarded.

Run just these tests:

```sh
python -m unittest discover -s tests -p test_edge_cases.py -v
```

- System speech requests, missing own-voice recordings, denied microphone,
  real MediaRecorder processing using an oscillator stream, IndexedDB persistence,

Speech synthesis is stubbed because headless machines have no reliable OS voice.
The microphone success test supplies a real Web Audio stream to the real
MediaRecorder; the denial test supplies a permission error. English decoding and
playback are not stubbed. Playback tests observe actual audio source scheduling
and non-silent buffers; they cannot establish what a human hears through speakers.
Hardware, macOS/Arc site permissions, and OS speech quality require manual checks.

GitHub Actions runs this suite on pushes and pull requests. These are regression
checks for the basic workflows, not a claim of exhaustive branch coverage or
cross-browser compatibility.

## Audio failures and accessibility

`test_audio_failures.py` exercises a suspended AudioContext, sound replay,
training pause/resume with a frozen audio clock, corrupt embedded MP3s and
recorded audio, corrupt saved PCM, and a very quiet microphone. Real Web Audio,
MediaRecorder, codec decoding, and IndexedDB remain in use. Test microphone
streams are generated by an oscillator; the corruption test replaces recorder
output with invalid bytes. These tests cannot verify physical speaker output.

`test_accessibility.py` checks a training workflow using Tab/Enter/arrow keys,
mobile menu focus trapping and return, visible focus outlines, theory-cell
keyboard activation, accessible button names, and action/digit names for the
recording controls. These are focused accessibility regressions, not a complete
WCAG audit or a screen-reader compatibility claim.

## Responsive layout and screenshots

`test_visual.py` checks all eight navigation destinations and sequence memo,
recall, and result screens for horizontal overflow at 320×720, 390×844,
768×1024, and 1440×900. Twenty full-page screenshots cover Theory, Questions,
Digits, Binary, and Audio at those four sizes. Initial baselines were generated
and visually inspected in Linux Chromium; browser version is recorded in
`screenshots/metadata.json`. Fonts and browser/OS rendering can differ across
machines, so review actual/diff artifacts before updating baselines on another
platform; use a matching Chromium via `CHROMIUM_PATH` for reproduction.

Normal runs compare against `tests/screenshots/` and never update the baselines.
Color differences of at most 25/255 per channel are ignored; at most 1% of pixels
may differ materially, and image dimensions must match. A control test verifies
that a deliberate 100-pixel layout shift exceeds the threshold. Animations are
disabled during capture, fonts are awaited, and scroll/focus state is reset.

To regenerate baselines after reviewing an intentional visual change:

```sh
UPDATE_SCREENSHOTS=1 python -m unittest discover -s tests -p test_visual.py -v
```

Actual images and mismatch diff images go to ignored `test-results/visual/`.
GitHub Actions uploads this directory as `visual-test-results`, even if other
tests fail. CI artifact upload configuration was added; the remote workflow has
not been executed during this task.

## New application features

`test_features.py` adds 19 checks for personal words/descriptions/pictures,
persistence and reset, escaping and rejected images, JSON downloads and imports,
voice and settings round trips, confirmation and invalid data rejection, quota
and transaction rollback, adaptive thresholds/limits/tempo, mistake analysis,
manifest/icons, offline English playback, GitHub Pages subpath scope, and explicit
Service Worker updates with old-cache cleanup.

The app's offline cache version is checked with:

```sh
python tools/update-pwa-cache.py --check
```

After editing offline assets, run the generator without `--check` before releasing.
Tests use fresh browser contexts; the PWA update test serves a versioned worker
from an isolated test server and never edits production files.
